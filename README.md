# Steamoji Kelowna File Server

## Running
Place repo inside folder (name doesn't matter), with the "apprentices" folder as a sibling

Uses [copyparty](https://github.com/9001/copyparty), runs on most Python versions. Version >=3.14 is needed for reflink deduplication support. 

























# motivations & goals
we currently use Onedrive, which is ineffective for the purpose of storing apprentice projects. syncing large projects can take weeks, and data is lost due to sync errors. as well, apprentices can easily modify the entire filesystem as they please. it is a bad tool for file syncronization in a LAN environment.

- speed
    - onedrive is slow. not to mention the laptops use DRAM-less SSDs. going local and keeping as much of the data on the server and off the clients is a good way to minimize these issues.

- security
    - apprentices have access to the whole file system. this is bad and has caused issues. im surprised it hasn't caused more issues

- sync correctness
    - onedrive struggles with small source code files, and refuses to sync certain others. unity projects in particular run into issues
    - if large changes are made, small changes will take so long to sync that correctness is broken

- backups
    - as far as I'm aware, there are no proper backups for the apprentice folders. i shutter while imagining the situation in which everything is lost

## solutions

i chose copyparty as a file server due to its ease of use, wide compatability, strong security, and modern features that many fs solutions lack.


- speed
    - copyparty is FAST, and handling things over LAN should make a big difference
    - having the entire fs mirrored on every device is an odd solution. most files are small and take little time to move.
    - [ ] dedup? maybe try dedup in facilitator volume and see if it works in sub volumes?


- security
    - apprentices only access their own folder, with each apprentice folder being a separate volume with an associated login in copyparty
        - logins are generated by generate_auth.py.
    - separate admin login for whole system management.


- sync correctness
    - handled by copyparty. conf is set to maximise correctness


- backups
    - will need to be done manually. copyparty's DB is be able to rebuild on restoration
